# M4：具身智能入门与一个仿真任务

预计 35–55 小时。来源：[Embodied-AI-Guide](https://github.com/TianxingChen/Embodied-AI-Guide)。目标限定为领域地图、必要机器人概念，以及一个仿真操作任务。**当前完成范围设计，尚未安装仿真环境、采集数据或训练策略。**

## 前置和范围

M1 的视觉、网络与训练评估是前置；模仿学习路线不要求先学完所有 RL。选择 RL 策略时用 M3；选择语言条件/VLA 分支时再用 M2。不要把相通误解为只学神经网络就具备机器人控制基础。

| 内容 | 指南对应部分 | 预算 |
|---|---|---:|
| 具身任务、观测/动作/策略、仿真与数据集 | 算法和基础设施索引 | 5–8h |
| 坐标系、位姿、运动学、控制频率与动作表示 | 机器人基础/控制条目，按当前任务补 | 7–10h |
| 一个仿真任务的数据、策略训练与评估 | RoboTwin 2.0 实战路线 | 18–29h |
| 失败分析、泛化条件与复述 | 回到任务代码和实验记录 | 5–8h |

不包含全部 SLAM/ROS、真实硬件部署、全部数据集或所有外链课程。

## 实验设计

优先沿指南的 RoboTwin 2.0 / ACT 路线选择一个任务，例如上游演示的 `beat_block_hammer`。正式开始前重新核验其固定版本和服务器图形/仿真兼容性，再确定演示数与训练规模。

1. 先记录 observation/action 的含义、坐标系、维度、控制频率、成功条件和 episode 结束方式。
2. 运行少量演示或已有数据的加载，检查相机、关节与动作的时间对齐；成功后再扩展数据量。
3. 训练一个小型模仿策略，与可用基线比较；保存配置、训练 loss 和评估轨迹。
4. 固定评估 seed 与 episode 数，报告成功次数/总次数；归纳至少两类失败，说明对新物体、新位置或新相机是否评估过。

指南给出的实战阶段以天为单位，不能直接等价为我们的 GPU 小时；环境构建、数据采集和仿真速度有很大差异。当前服务器显存具备尝试条件，但未验证 RoboTwin 兼容性与实际耗时，若超预算则先缩小数据/步数，保留流程学习目标。

## 完成门槛

能从“相机和机器人状态”追踪到“动作执行和成功判定”；解释 behavior cloning 与 RL 的目标和数据差异；指出闭环执行中的分布偏移；给出一个可重跑的任务配置及失败视频/轨迹索引。单一任务成功不代表掌握具身智能或证明真实机器人泛化。
